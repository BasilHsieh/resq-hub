# 跑研究

**為什麼有這個流程**（DECISIONS D-20）：Basil 的時間比 token 少。每週重置前沒用完的額度拿來做研究；Basil 只讀每題最後那五行。狀態在 [研究清單](../../../knowledge/研究清單.md)，流程在這裡。

---

## 0. 丟進研究清單（Basil 給來源時）

- **連結**：記進研究清單的「收件匣」——日期、連結、Basil 的原話（沒說就空著）。**不要問他為什麼給**，處理時自己判斷它在回答哪一題。
- **檔案**：Basil 拖進主 checkout 的 `raw/收件匣/`。worktree 裡沒有 `raw/`（不進 git），用這個找：

  ```bash
  RAW="$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")/raw"
  ls "$RAW/收件匣"
  ```

- 只是記下來的話到這裡就結束；Basil 說「跑研究」才往下。

## 1. 先看額度

用 `mcp__ccd_session_mgmt__get_usage` 記下 5 小時與每週的 %、重置時間。

- 每週 ≥ 90% 或 5 小時 ≥ 85%：不開新題，只把做到一半的收尾。
- 每做完一題再看一次，把用掉的 % 寫進那題的紀錄——之後排程要靠這個數字。

## 2. 挑題

順序：**收件匣 → 🔥（掛在 🔥 的 U-XX 上的）→ 其他 ⏳ → 消化**。一次一題。

- 收件匣的來源：先判斷它在回答哪一題，沒有就開新題，再照下面做。
- 題目一輪做不完就拆，拆出來的寫回清單。
- **不做「更多框架綜合」**（[馬太鞍溪觀察](../../../knowledge/fieldwork/馬太鞍溪觀察_basil_2026.md) 第六節）：每一題都要說得出它會改變哪個 D／U、手冊哪一段、工具的哪個決定，說不出來就排到最後。

## 3. 找來源

- 派 2–4 個 agent（`general-purpose`，`model: sonnet`），一個角度一個，背景執行。簡報要自帶背景（agent 看不到對話）、列出 repo 已經有的（不用重找）、指定用當地語言搜尋、限制工具呼叫次數與報告長度。
- 每份報告必須有：完整書目、URL、讀到的程度〔全文〕〔摘要〕〔二手〕、數字與關鍵主張的原文短句。只能引用真的打開過的來源，打不開就寫打不開。
- **影音**：有字幕或逐字稿的才處理；沒有的記在清單上，等 Basil 給檔。**書**：沒有檔就只能用二手（書評、出版社介紹），標〔二手〕。

## 4. 寫成文件

- 放 `knowledge/context/`，命名照 CLAUDE.md（多來源用 `主題_年.md`）。frontmatter 必填 `tags` `date` `summary` `priority` `citation`（多來源寫「非單一文獻，各條附 URL」）。
- **每條主張後面標證據等級**：〔全文〕〔摘要〕〔二手〕〔推論〕。〔推論〕＝Claude 的讀法，不是來源說的。
- 文件一定要有兩節：
  - `## 這改變了什麼`（緊接在發現之後、來源之前）：哪條 D／U 被支撐、被挑戰、需要修訂；手冊哪一句有了出處；工具的哪個決定多了依據。**挑戰現有決定的寫最前面。**
  - `## 關聯`（最後一節）：雙向（見 wrap-up 第 3 步）。需要改 framework 的，在對方 frontmatter 加 `revision_pending`，不要順手改寫。
- 書目與 URL 集中在「來源」一節；只見書目、沒讀到內容的另列「線索」，不當證據。
- Basil 的口述仍是「單一觀察者、待驗證」。文獻跟它不同時兩邊都留：不用文獻蓋掉它，也不用它蓋掉文獻；只採研究的框架，不採媒體的框架。

## 5. 核對

另派一個 agent（`model: sonnet` 即可）逐條打開文件裡的 URL，比對主張與來源是否一致、證據等級有沒有標對。**要它用確定性的方法核**：curl 把原文存進 scratchpad 裡一個新的空資料夾、PDF 用 pdftotext 轉文字、再 grep 原句；被擋才改用 WebFetch 並註明——找來源的 agent 多半靠網頁擷取工具轉出引句，同一種工具核不出它的錯。要它回報：錯的、誇大的、標錯等級的、打不開的。全部修掉或降級（〔全文〕→〔摘要〕、刪掉站不住的句子）。

## 6. 更新清單

- 這一題：狀態、產出連結、**五行**、用掉的額度。
- 這輪發現的新問題加進清單，寫清楚它要回答什麼。
- 收件匣處理完的劃掉並連到產出；`raw/收件匣/` 的檔移到 `raw/pdfs/` 或 `raw/md/`（移，不刪）。
- [文獻處理進度](../../../knowledge/文獻處理進度.md) 加一列。

## 7. 收工

跑 `python3 scripts/kb.py all`，照 `.claude/skills/wrap-up/` 開 PR，**不 merge**。commit 前綴 `知識庫｜`。PR 內文放每題的五行與用掉的額度。

---

## 之後：排程（還沒做）

先手動跑兩輪、知道一題實際用掉幾 %，再加排程。條件：離每週重置不到幾個小時、而且還有剩，才跑；碰到第 1 步的門檻就停。排程只在 app 開著時會跑，app 關著會等到下次打開才跑——那時可能已經重置了，所以每次開跑都要先做第 1 步。
