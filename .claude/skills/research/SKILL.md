# 跑研究

**為什麼有這個流程**（DECISIONS D-20）：Basil 的時間比 token 少。每週重置前沒用完的額度拿來做研究；Basil 只讀每批最後那一頁。

**三份檔案，各管一件事**：
- [研究方向](../../../knowledge/研究方向.md)：範圍（Basil 定）、兩種研究的分工、論點看板。
- [案例比較表](../../../knowledge/案例比較表.md)：探索的欄位（就是計畫書）、總表、挖案例的佇列。
- [研究清單](../../../knowledge/研究清單.md)：收件匣、每一題的狀態與紀錄。

**研究分兩種**（D-20 的 2026-11-13 補）：
- **探索**——那裡發生了什麼？一次一個案例，照欄位填。欄位固定、框錯的風險低，排程可以自己挑、自己跑。論點會從這裡長出來（Basil）。
- **檢驗**——這條論點站不站得住？一次一條論點，事先寫好什麼算推翻。問法幾乎決定答案，所以 **Basil 看過三行才跑**。

## 0. 丟進研究清單（Basil 給來源時）

- **連結**：記進研究清單的「收件匣」——日期、連結、Basil 的原話（沒說就空著）。**不要問他為什麼給**，處理時自己判斷它在回答哪一題。
- **檔案**：Basil 拖進主 checkout 的 `raw/收件匣/`。worktree 裡沒有 `raw/`（不進 git），用這個找：

  ```bash
  RAW="$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")/raw"
  ls "$RAW/收件匣"
  ```

- 只是記下來的話到這裡就結束；Basil 說「跑研究」才往下。

## 1. 先看額度

用 `mcp__ccd_session_mgmt__get_usage` 記下 5 小時與每週的 %、重置時間。

- 每週 ≥ 90% 或 5 小時 ≥ 85%：不開新的工作，只把做到一半的收尾。
- 每做完一份工作再看一次，把用掉的 % 寫進研究清單的紀錄——排程要靠這個數字。

## 2. 挑工作

順序：**收件匣 → 已點頭的檢驗題 → 案例佇列 → 消化**。一個案例、一題檢驗、一項消化，各算一份工作。

- **收件匣**的來源：先判斷它是哪個案例的材料（併進那個案例）、哪條論點的證據（併進看板）、還是一個新題（寫成三行，等點頭）。
- **檢驗題只做研究清單上標「✔ 已點頭」的。** 研究自己冒出來的新題、探索的「沒想到的事」，寫成三行放進清單、標「📝 待點頭」，這一輪不做——2026-11-10 那批有兩題是前幾批研究自己冒出來的，沒經過 Basil 就跑了。
- **案例**照案例比較表第三節的順序挖。
- **不做**：範圍外的題（研究方向第一節），除非 Basil 指定；產品細節題（公告要多早發、畫面顯示什麼）標「⏸ 交給演練」；「更多框架綜合」（[馬太鞍溪觀察](../../../knowledge/fieldwork/馬太鞍溪觀察_basil_2026.md) 第六節）。
- 一份工作一輪做不完就拆，拆出來的寫回清單。

## 3. 動手前寫計畫書

- **探索**：計畫書就是案例比較表的欄位。另外寫這個案例的起點：repo 已經有的（不用重找）、已知還沒打開的來源、要用的語言與關鍵字。
- **檢驗**：三行，Basil 點頭的就是這三行——
  1. **測**哪條論點（看板上的編號與那句話）。
  2. 什麼結果算**推翻**、什麼算**支持**。
  3. **找哪種人**。類比的對象要有同樣的動機結構：自願、去哪都可以、可以不去（捐血、捐款與群眾募資、別的災區的志工）。有非去不可需求的（通勤、急診）只能借跟需求無關的機制，量級不能搬（Basil 2026-11-11）。

  另外給 agent 的（Basil 不用看）：什麼樣的資料算數、什麼不算；語言；來源類型。
- **題目寫短**：寫要測什麼、找哪種人，**不替 agent 決定去哪找**。2026-11-10 的題目點名了地鐵、急診、導航、遊樂園，agent 就照著找；點名的領域會把搜尋框死，也擋掉 Basil 要的「打開想法」。已知的起點可以給，標「起點，不是範圍」。

## 4. 找來源

- 每份工作派 3 個 agent（`general-purpose`，`model: sonnet`），背景執行，同時跑：
  - **探索**依來源類型分工：①官方與 NGO 的檢討報告、統計；②學術研究；③新聞與當事人的說法，特別是頭幾天。三個都拿到完整欄位，找到什麼填什麼，填不到的寫「查了，沒有」。
  - **檢驗**依立場分工：①支持的一方；②**反方**——專找能推翻這條論點的證據，找不到要寫找了哪裡；③**開放**——只給論點與「找哪種人」，不給起點，自己找我們沒想到的例子。
- 簡報要自帶背景（agent 看不到對話）、列出 repo 已經有的（不用重找）、指定用當地語言搜尋。工具呼叫約 50 次、報告 ≤ 2500 字（2026-11-10 那批每個 agent 約 30 次、報告 ≤ 1500 字，太淺）。
- 每份報告必須有：完整書目、URL、讀到的程度〔全文〕〔摘要〕〔二手〕、來源類型（見第 5 步）、數字與關鍵主張的原文短句；**怎麼找的**：用了哪些關鍵字、語言、網站或資料庫，哪些打不開。只能引用真的打開過的來源，打不開就寫打不開。
- **影音**：有字幕或逐字稿的才處理；沒有的記在清單上，等 Basil 給檔。**書**：沒有檔就只能用二手（書評、出版社介紹），標〔二手〕。

## 5. 寫成文件

- 放 `knowledge/context/`：探索寫成 `案例_地點事件_年.md`（年是事件的年），照案例比較表的欄位；檢驗照 CLAUDE.md 命名（多來源用 `主題_年.md`）。frontmatter 必填 `tags` `date` `summary` `priority` `citation`（多來源寫「非單一文獻，各條附 URL」）；案例的 tags 加 `案例`。
- **每條主張後面標讀到的程度**：〔全文〕〔摘要〕〔二手〕〔推論〕。〔推論〕＝Claude 的讀法，不是來源說的。
- **來源節的每一條另標類型**（強的在前，定義在研究方向第三節）：〔統計〕〔研究〕〔檢討〕〔官方〕〔報導〕〔自述〕。
- 文件一定要有：
  - **最前面**：檢驗寫「判決」——論點 N：支持／挑戰／推翻／沒影響，附最強的證據類型，沒影響寫一行就好；探索寫「碰到的論點」與「沒想到的事」。
  - `## 對決定與手冊的含義`：哪條 D／U 被支撐、被挑戰、需要修訂；手冊哪一句有了出處。挑戰現有決定的寫最前面。需要改 framework 的，在對方 frontmatter 加 `revision_pending`，不要順手改寫。
  - `## 怎麼找的`、`## 來源`（書目與 URL 集中在這；只見書目、沒讀到內容的另列「線索」，不當證據）、`## 找不到的`、`## 關聯`（最後一節，雙向，見 wrap-up 第 3 步）。
- Basil 的口述仍是「單一觀察者、待驗證」（〔自述〕）。文獻跟它不同時兩邊都留：不用文獻蓋掉它，也不用它蓋掉文獻；只採研究的框架，不採媒體的框架。

## 6. 審查（兩個 agent，都要派）

- **核引文**（`model: sonnet`）：逐條打開文件裡的 URL，比對主張與來源是否一致、讀到的程度有沒有標對。**用確定性的方法**：curl 把原文存進 scratchpad 裡一個新的空資料夾、PDF 用 pdftotext 轉文字、再 grep 原句；被擋才改用 WebFetch 並註明——找來源的 agent 多半靠網頁擷取工具轉出引句，同一種工具核不出它的錯。回報：錯的、誇大的、標錯等級的、打不開的。
- **核推論**（`model: sonnet`，另一個 agent）：讀文件與找來源的 agent 報告，回報四種問題——
  1. **對象不像**：類比的人有非去不可的需求；案例其實不是「政府量能不足、大量志工湧入」。
  2. **結論長大了**：幾處變成「全世界」、「有集中的入口」變成「派工」、「沒人量過」變成「被挑戰」。例：2026-11-12 Claude 把「R-01 看過的六處」說成「全世界大型清淤幾乎都是派工」，其實六處裡的亞爾河谷刻意不派工。每句引文都對，錯在推論一路長大——核引文抓不到這種錯。
  3. **有別的解釋**，文件沒提。
  4. **判決比證據強**：只有報導就寫「推翻」、只有一處就寫成規律。
- 全部修掉或降級（〔全文〕→〔摘要〕、「推翻」→「挑戰」、刪掉站不住的句子）。

## 7. 更新看板、總表、清單

- **論點看板**（研究方向第三節）：每條被碰到的論點，加一行證據（方向、強度、連結），必要時改狀態。「被推翻」要兩個以上互相獨立的來源，而且至少一個是統計、研究或檢討。**論點本身的文字不改**——那是 Basil 的話；新的論點放「候選」。
- **案例比較表**：總表那一列、佇列的狀態。
- **研究清單**：這份工作的狀態、產出、判決、用掉的額度；新題寫成三行、標「📝 待點頭」。收件匣處理完的劃掉並連到產出；`raw/收件匣/` 的檔移到 `raw/pdfs/` 或 `raw/md/`（移，不刪）。
- [文獻處理進度](../../../knowledge/文獻處理進度.md) 加一列。

## 8. 給 Basil 的一頁（每批一份）

寫在 PR 內文與那次 session 的最後一則訊息，10 行以內。白話、不用代號（用到就先說白話）；圍繞一個現場的畫面講，不要列術語。

- **論點**：哪幾條動了，一條一行。例：「論點 3（派工跟不上現場）：被挑戰〔檢討〕——倉敷的志工中心派出去的人……」
- **沒想到的事**：最多兩條。
- **要問你的現場題**：最多三題，「這裡是這樣，光復也是嗎？」
- **等你點頭的新題**：幾題（三行在研究清單上）。
- 做了什麼、用掉的額度、PR 連結、檢查過了沒。

## 9. 收工

跑 `python3 scripts/kb.py all`，照 `.claude/skills/wrap-up/` 開 PR，**不 merge**。commit 前綴 `知識庫｜`，一份工作一個 commit。

## 排程（2026-10-28 上線；2026-11-13 改成探索＋檢驗）

每週二 23:00（台北時間）自動跑一批。指令在 `~/.claude/scheduled-tasks/resq-research-weekly/SKILL.md`（不進 git）；要改時間或規則，跟 Claude 說，或到 app 側邊欄的「排程」改。

- **為什麼是週二 23:00**：週額度在週三中午 12:00 重置，這時離重置約 13 小時，做得完一批；選深夜，是為了不跟 Basil 週三早上搶 5 小時額度。重置時間變了，排程要跟著改。
- **開跑前**：先做第 1 步。另外兩條：離週額度重置超過 24 小時不跑（app 在排定時間是關著的、重置後才補跑，用的會是新一週的額度）；離重置不到 1 小時也不跑。
- **一次最多 4 份工作**：已點頭的檢驗題優先（最多 1 份），其次照佇列挖案例，額度還有剩才做消化。每份工作 5 個 agent（3 個找來源、2 個審查），照 2026-10-28 那批每題 3–4 個 agent 的數字，一份約用掉 5 小時額度的 10–20%、週額度的 1–3%；碰到第 1 步的門檻就停。一份工作一個 commit，最後開一個 PR，不 merge。
- **在自己的 worktree 做**（用 EnterWorktree 開 `research-日期`），不動主資料夾的檔案。
- **限制**：app 開著才會跑。排程存成 Auto 模式；碰到 app 本身的動作（改設定、資料夾權限）會被拒絕，照樣往下做。Claude 不能替 Basil 按「Run now」試跑（Auto 模式會擋），要試跑得由 Basil 自己按。
- 回報寫在那次排程自己的 session 裡，Basil 在那裡說「你 merge」就好。
