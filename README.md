# ResQ Hub

> 專案名稱暫定。

台灣災害協作的**研究與規格庫**——從整理第一手經驗出發，抽象成可複製的協作模式，最終長成一份能交給別人實作的工具規格。

---

## 起源

2025 年花蓮馬太鞍溪堰塞湖溢流救災。政府確認全期 **45 萬人次**志工投入。

民間動員能量極強，但資訊流極度分散：需求重複回報、志工重複出動、物資去向難追蹤、事後沒有可回顧的紀錄。

問題不是工具不夠，而是缺乏可被複製的協作模式與資訊架構。

核心問題：

> **「我現在過去，是否真的還幫得上忙？」**

---

## 目前的答案

**現有救災系統以「有無組織歸屬」當入場門檻，把自發性志工擋在外面。ResQ Hub 不這樣做。**

自發性志工（spontaneous／unaffiliated）——沒有組織歸屬的個人。FEMA 說 "affiliate before you volunteer"，內政部《強韌台灣計畫》167 頁沒有這個欄位，而花蓮光復來了 45 萬人次。

**排除是不對稱的**：為最低組織度的人設計，慈濟也能用；為組織設計，個人就進不來。所以不排除他們不是選邊站，是取得最大公約數的必要條件。

> **組織性不是入場券，是一種可以被快速賦予的狀態。**

- **範圍**：先做現場資訊的最大公約數——一個人跟一個團體需要的資訊大量重疊，先做重疊那層。團體間的橫向溝通排在後面（是排序，不是排除）。
- **介入窗口**：災後 72 小時 ~ 3 週（清淤期）。不做急性搜救期，不做長期重建期。
- **做共同視野，不做媒合**——廣播需求狀態，讓自主的人自己流過去。
- **政府是 bonus，不是 precondition**——價值先對志工與災民兌現。

完整論證見 [output/vision.md](output/vision.md)；決策與未決問題見 [DECISIONS.md](DECISIONS.md)。

## 這個 repo 是什麼

**研究／規格 repo，不是產品 repo。** 這裡做到 prototype 與規格為止，實作會另外找人。

| | |
|---|---|
| [INDEX.md](INDEX.md) | 知識庫索引與導覽入口——**從這裡開始** |
| [ARCHITECTURE.md](ARCHITECTURE.md) | 4 張 mermaid 圖，一頁看完整個專案 |

| `output/` | 對外 Vision 與（未來的）工具規格 |

---

## 三層架構

| 層次 | 目標 |
|---|---|
| **經驗層** | 保留完整脈絡——誰看到了什麼、當下手上有哪些資訊、為什麼會誤判 |
| **模式層** | 從多個經驗抽象出可複製的原則與角色分工 |
| **工具層** | 災時降低資訊落差的數位工具 |

這三層也是開發順序，先把經驗留下來，才有條件做工具。
