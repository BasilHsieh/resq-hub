# 到了按一下的轉換率（2026）

> **這份是什麼**：[研究清單](../研究清單.md) R-14，給 [DECISIONS](../../DECISIONS.md) D-15「看的人≈回報的人」與成立條件 ②「第一個到的人會按一下」找外部證據。R-04 已經找到「有紀錄的系統裡貢獻的人都是少數」，但那些是編地圖、整理消息，不是「到了按一下」這麼便宜又在現場的動作。2026-11-03 由兩個 agent 分頭找（「通知 → 接受 → 到場」有實測的 CPR 志工 app；現場一鍵回報的比率與動機），Claude 整理，再由另一個 agent 用原文核對。

---

## 一句話

**沒有人公開過「看到清單 → 到場按一下」的漏斗。** 最接近的 CPR 志工 app 連人命關天、有派遣中心，都不靠志工自己按來知道誰到了——到場是事後問卷補的，還缺兩成。災時大量的簡短回報會出現，但沒人分得出被提醒與自己想起來的各占多少。ResQ Hub 的按鈕沒有推播可以提醒：它落在沒有證據的那一格。

---

## 一、最接近的漏斗：CPR 志工 app

結構：有人倒下 → 派遣中心通知附近幾百公尺到幾公里內、事先註冊過的志工 → 志工按接受 → 前往 → 到場。跟 ResQ Hub 差很多：有人命、有急迫性、有人挑人推播；ResQ Hub 是沒人挑、公開清單、自己選。〔推論〕方向上我們只會更難，沒找到反例。

| 系統 | 漏斗 | 讀到的程度 |
|---|---|---|
| 澳洲維多利亞＋紐西蘭（GoodSAM）的志工問卷 | 1,985 位受訪者：看到通知 75.6%、接受 37.7%、到場 27.1%、實際照護 14.3%〔摘要〕 | [1] |
| 美國 PulsePoint | 問卷回收 21.4%；收到通知後有行動的 23%，有行動的人裡 28% 沒到〔摘要〕 | [2] |
| 丹麥 Heartrunner | 1,877 件裡 91.9% 至少一人接受（以事件算，不是以人算）；到場靠派遣後約 90 分鐘寄出的問卷，接受者約兩成沒回答〔全文〕 | [3] |

- 〔推論〕以「看到通知」為 100：約一半接受、約三分之一到場、約五分之一真的動手（澳洲＋紐西蘭那份）。分母是回問卷的人，比較積極的人才回，真實數字只會更低。
- **「到了沒」沒有一個系統靠志工自己按**：丹麥用事後問卷，回答的人 99.7% 說有到，但約兩成接受者沒回答，這些人到了沒不知道；接受與否 app 有紀錄，論文只用問卷評估到場，沒提到其他驗證方式〔全文〕[3]。〔推論〕99.7% 不能當樂觀的證據——那是回答的人裡的比例。
- **到了常常不需要**：PulsePoint 到場的人只有 32% 真的遇到需要急救的人〔摘要〕[2]；瑞典 14 位志工描述的 31 次警報裡，接受 25 次，其中 11 次「到了但不需要」〔全文〕[4]。〔推論〕對應 ResQ Hub：到了發現人夠了、已經清完，這正是要按 🟠／✅ 的時刻，也正是最可能覺得「沒事、走了」的時刻。
- **志工想知道還有誰也被叫了**：瑞典的訪談裡，志工希望看到還有多少人也收到通知〔全文〕[4]。〔推論〕支撐 U-12「已有 N 人」那一類的擁擠訊號——但 R-05 已提醒，意向數字要跟到場的人按的分開。

## 二、災時的簡短回報：有量，沒有分母

- **日本 Yahoo!防災速報「災害地圖」**：使用者可以在災害地圖上投稿身邊的河川氾濫、增水、強風等狀況。2020 年 7 月豪雨約一個月內，災害狀況 7.8 萬件以上、停電等生活設施狀況 33 萬件以上；當時 app 用戶 2,000 萬（公司新聞稿）〔全文〕[5]。〔推論〕分母是全國用戶、不是災區的人，也不知道多少人投稿，算不出比率；能說的只有：裝了 app、摩擦很低的回報，災時真的會大量出現。新聞稿沒寫投稿是不是收到通知後才做的。
- **雅加達 PetaJakarta**：2014–15 年雨季，bot 對雅加達的推特用戶發出 8.9 萬則以上的邀請；平台另寫上線以來「數以千計」的人用手機回報（不一定來自邀請），尖峰每小時超過 3,000 名使用者（大學新聞稿）〔全文〕[6]。邀請數有、回覆數沒有，轉換率算不出來。後繼的 PetaBencana 讓人回覆 #flood、bot 再給連結填水深與照片〔全文〕[7]。
- **美國 mPING（天氣現象回報 app）**：2013 年下載超過 3 萬、回報超過 20 萬筆〔摘要〕[8]。只有總量，沒有「下載後從不回報」的比例。
- **被提醒、有報酬、有義務時的上限**：經驗取樣法（研究參與者在固定時間被手機提醒填答）的統合分析，79 項研究合規率 78.7%〔全文〕[9]。〔推論〕這是被叫、有錢、有義務的上限；樣本是精神疾患的研究參與者，不是路人志工。
- **為什麼按**：Waze 的訪談研究，互惠是一般使用者分享資訊的重要誘因——自己也用別人的資料〔摘要〕[10]。〔推論〕跟 U-12「按『人夠了』是在回答自己『那我去哪』」同方向：按的人自己會用到。

## 三、沒找到的（這一題的主要結果）

- 「看到清單 → 點開 → 照著去 → 到了按一下」任何一段的實測。
- **被提醒 vs 沒人提醒**的回報率比較——找到的大量回報都分不出是哪一種。
- Waze 活躍用戶裡有多少人回報過路況；Facebook 平安報到在災區人口裡的比例；Google 地圖「這家店還開著嗎」的回答率——都只有絕對數字或沒有數字。
- Crisis Cleanup（美國）認領工單後有多少被標為完成、多少認領過期——只找到「認領了就要在 6 天內做完」這類規則（見「線索」）。
- 2024 花蓮地震共用表單的回報筆數。

## 這改變了什麼

1. **挑戰 D-15 條件 ②（第一個到的人會按一下）**：連有人命、有派遣中心的 CPR 志工 app 都不靠志工自己按來知道誰到了——事後問卷補，丹麥還缺兩成；找到的大量回報都分不出是被提醒的還是自己按的。〔推論〕「沒人按」不等於「沒人去」，ResQ Hub 的 ⚪「沒人去過」會系統性地多報，去過、沒按的戶會繼續吸人（U-12 的一種）。→ 規格 ⚪ 的意思其實是「還沒有人回報」；畫面要不要照實寫，交給 Basil（spec 已標待修訂）。
2. **按鈕沒人提醒**：網頁、不裝 app，就沒有推播可以在到場時叫人按；提醒有沒有用，這次也沒找到比較〔推論〕。能提醒的只剩出發前與到場時看得到的東西：手冊與車站 QR code 寫「到了按一下」、出發前打開的那一頁到場時還開著就問「到了嗎？」。這是設計題，沒有證據哪一種有用——演練時比較。
3. **兵推的回報率要掃，範圍有了量級**：R-04 已建議別把「看的人≈回報的人」固定成 1。CPR app 從看到通知到到場約三分之一、真正動手約五分之一（積極受訪者、有人命）；被叫、有報酬時上限約八成。〔推論〕掃描範圍可以從一成到八成，在兵推 README §5c 那張表上看「沒人去過」在哪個回報率以下開始失去鑑別力。
4. **到場常常不需要，這時最容易不按**：PulsePoint 到場只有約三成真的遇到需要急救的人，瑞典 25 次接受裡 11 次「到了不需要」。〔推論〕ResQ Hub 的 🟠「人夠了」、✅「清完了」正是「到了不需要」的時刻——要讓這一下的回報看起來有用（它擋住下一個白跑的人，U-12），否則就是最先被跳過的。
5. **U-19 第 3 題的答案只能自己量**：沒有任何來源公開過這個漏斗，找不到本身就是結論。第一次實地演練要記四個數：打開的人、照著去的人（問卷或到場點名）、到了的人、到了有按的人；最後兩個的差就是條件 ② 的答案。
