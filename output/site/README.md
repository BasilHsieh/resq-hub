# 網站（D-21）

把 repo 裡給人看的頁面做成靜態網站。**內容只在 repo 裡改，網站不另外維護一份。**

## 怎麼建

```bash
python3 scripts/site.py
```

預覽：全部頁面，掛「草稿預覽」標記，輸出到 `_site/`（不進 repo）。

```bash
python3 scripts/site.py --public
```

正式：只放 `status: 對外發布` 的頁。

```bash
python3 scripts/site.py --artifact
```

預覽，首頁照 claude.ai artifact 的格式輸出（發成只有發起人看得到的連結）。

本機看：`python3 -m http.server 8765 --directory _site`，打開 http://localhost:8765 。CI 每個 PR 都會建一次，建不起來就擋。

## 哪些頁會上網站

- 手冊（`output/handbook/`）、知識庫（`output/knowledge/`）、[出處與著作權](../出處與著作權.md)。README 不上。
- 每一頁 frontmatter 要有 `slug`：它在網站上的網址，英文小寫與連字號（例如 `where-no-one-goes`）。`kb.py` 檢查有沒有、重不重複。
- **正式網站只放 `status: 對外發布` 的頁**，狀態只有發起人能改。手冊的保險與健康兩節，發布前要懂的人看過（出處與著作權 §四）。
- 頁面裡連到研究筆記（`knowledge/`）或別的 repo 檔案的連結，網站上會連到 GitHub。
- 知識庫的順序照 `output/knowledge/README.md` 表格裡的順序。

## 研究方法頁

`output/knowledge/研究怎麼做.md`，在 GitHub 上一樣讀得懂；網站多做兩件事：

- **流程圖**：「一份研究怎麼跑」那一節，每一步寫成 `### N. 名稱` 加四行（誰、做什麼、留下什麼、例子）。網站把它畫成三條線：「誰」寫發起人、Claude 或排程、AI 助手，決定那一步在哪一條線。
- **研究現在跑到哪**：`<!-- site:status -->` 到 `<!-- /site:status -->` 之間，網站換成自動產生的進度——論點看板（`knowledge/研究方向.md`）、案例佇列（`knowledge/案例比較表.md`）、等點頭的題（`knowledge/研究清單.md`）。研究筆記寫 Basil 的地方，網站上寫「發起人」。

研究流程（`.claude/skills/research/`）改了，這一頁要跟著改。

## 首頁

一份頭版（D-21，2026-11-14 發起人選）。第一屏回答「你們發現了什麼」；字全部從 repo 來，不另外寫。

- **頭條**：知識庫 README 表格的第一列。問句是表格第一欄，大字是那一頁「先說結論」第一條，下面列其餘幾條。**要換頭條，就換表格的順序。**
- **其他問題**：表格裡其餘有「先說結論」的頁，一題一句（第一條）。論點頁與研究方法頁不列在這裡，改由右欄連過去。
- **句子怎麼取**：每一條取第一句；下一句是「但」「不過」「只是」「可是」開頭的，一起帶（不然只剩一半的意思）；「（見下）」這種只在原頁有意義的字拿掉；註腳號不帶。所以「先說結論」每一條的第一句要能自己站得住。
- **右欄**：「要去災區幫忙？」連到手冊〈出發前〉（手機上排最前面）；「還不確定的」是論點看板（`knowledge/研究方向.md`）每一條與狀態；「讀了哪些地方」是案例佇列（`knowledge/案例比較表.md`）照狀態分組、照年份排。
- 不用卡片、不用大數字，層次只靠字的大小與細線。否決過的排法與理由見 DECISIONS D-21。

## 長相

- `site.css`：版面與元件。顏色、間距、圓角、字型的值來自設計系統的 `tokens.json`（建置時產生在 CSS 最前面），這裡不重寫。
- 設計系統只管災區現場的手機畫面；網站是坐著讀的長文，所以閱讀寬度、註腳、表格是網站自己的。深色主題的顏色由 `scripts/ds.py` 從同一個主色算（`derive_dark`），建置時產生在 CSS 最前面，不手調。
- 照設計系統的（第三版，2026-11-13）：只用裝置內建字型；顏色少用，主色（淺綠、上面放黑字）只給要你注意的狀態（「已對外發布」「有支持」、案例做完、流程圖裡發起人那一條），連結用深綠的字；不塗淡色塊；小圓角、不做膠囊；形狀也帶意思（虛線＝還沒確定、實線框＝挑戰、實心＝確定的）；文字對比 6.5:1 以上；草稿標記條跟演習標記同一種長相。
- 研究方法頁的流程圖裡，發起人那一條用主色：這一頁唯一有顏色的地方，因為讀者最該一眼看到的是「發起人在哪裡出手」。
- `site.js`：只畫流程圖的連接線；沒有它，網站照樣能讀。

## 還沒定

- 面向工具的研究要不要放上網站（它是寫給做工具的人看的）。
- 網站放在哪（Firebase Hosting 或 GitHub Pages）、網域（網址要對外之前再買）。
- 工具掛在同一個網域的子網域還是路徑。
- 網站要不要像志工頁一樣做截圖比對（D-19）。
- 案例頁（一處一頁）出來之後，首頁要不要分開列。現在的程式會把有「先說結論」的案例頁跟其他問題列在一起。
