# ResQ Hub 設計系統

給災區現場的志工：太陽底下、戴著手套，一眼看懂、一下按到。

它服務一種畫面、一種人：**已經在災區現場的志工，剛做完一戶，站在門口，拿著手機，要決定下一戶去哪**。中繼站（筆電、坐著、一天登記幾十筆）與遠端整理（桌機、看整盤）的資訊密度完全不同，不在這一套裡。

第二版（2026-09-27）：長相改成「清楚大膽」——大數字、色塊、膠囊按鈕、大圓角；顏色改成從一個主色推出來。決策與理由記在 repo 的 `output/spec/設計系統.md`；同意與需求的規則在 `output/spec/資料模型與狀態機.md` §0d；DECISIONS.md 的 D-12、D-15、D-16、D-17。

## 為誰設計

- **數位能力光譜很寬**：以最不熟手機的人為準——一次一個概念、字大、按鈕大、少字。
- **太陽下、戴手套、網路不穩**：這是規格裡的裝置條件（資料模型 §5），不是美術偏好。
- **手機只在休息和換地方時拿出來**看幾眼。每個畫面都要在幾秒內看懂。

## 內容原則（先於視覺）

1. **一個畫面只問一件事。** 回報頁把「屋主同意嗎」和「需要人嗎」分成兩塊，各自更新，只填你知道的那一項。
2. **一個標籤只講一件事。** 同意狀態和需求永遠分開顯示。不做「同意，還要人」這種一鍵兩義的按鈕。
3. **按鈕寫動作，不寫時機。** 「回報這一戶」，不是「我到了」。「更新同意狀態」，不是「編輯」。
4. **時間只有一種寫法**：今天「最後更新 14:26」，前一天「最後更新 昨天 08:40」，更早「最後更新 9/24 08:40」，沒有紀錄「還沒有紀錄」。不寫「1 小時前」「剛有人問過」。
5. **用現場的話**：「缺 5 人」「人夠了」「清完了」「要先問屋主」「暫時不用去」「走路 3 分鐘」。
6. **不說有沒有人在家。** 「沒人在家」「空屋」不是狀態，任何畫面都不出現（隱私與防盜）。「尚未取得同意」也不寫原因。
7. **範例一律用虛構地址**（甲街、乙路）。同意狀態不能掛在真實地址上。
8. **演習畫面從頭到尾掛演習標記**（DrillBanner）。

## 長相：清楚大膽

借的是 2026 年的共同語言，不是某一個平台：**大數字、色塊、膠囊按鈕、大圓角、答案放在大拇指按得到的地方**。真的做成 app 時，導覽列、系統按鈕會自動跟著平台（iPhone 的玻璃、Android 的 Material）；這套系統管的是內容：顏色、字、形狀、元件。

- **一眼先看到數字**：分類格的數量用 42px 的大數字，選中的那一格是主色加一個勾。
- **色塊代替框線**：沒選中的東西放在淺色塊（`tonal`）上，不用細框線圍起來——太陽下細線看不到，色塊看得到。
- **可以按的小東西一律膠囊形**；卡片 24px 圓角；一題一頁的答案按鈕 28px 圓角，圖示放在左邊的白圓裡。
- **答案放在畫面下方**：一題一頁的畫面，問題在上、答案在下，大拇指按得到。
- **不用半透明、不用陰影**：太陽下兩者都會消失。唯一的陰影是鍵盤焦點外框。

## 顏色：從一個主色推出來

主色是**靛** `oklch(0.48 0.15 276)`（`#4950b0`）——三個候選（靛、深青、墨）裡最現代、最親切，跟現場任何團體的顏色都不撞。其他顏色都是算出來的，`scripts/ds.py palette` 可以換主色重算，對比會自動檢查。

| 角色 | Token | 怎麼來的 | 用在哪 |
| --- | --- | --- | --- |
| 主色 | `action` `action-fg` | 靛，暗到白字對它至少 6.8:1 | 主要按鈕、選中的分類、強調框、連結 |
| 主色的淺色 | `action-soft` `action-ink` | 同一個色相，很淺；上面的字至少 7:1 | 已同意、分類說明框、已記下 |
| 缺人 | `need` `need-fg` | 主色的對面：杏橘 `oklch(0.91 0.06 60)` | **只給「缺 N 人」**——全畫面唯一的暖色 |
| 中性 | `ground` `surface` `tonal` `line` `line-strong` | 帶一點點主色的灰 | 底、卡片、沒選中的色塊、框 |
| 字 | `ink` `ink-2` `ink-3` | 同上，很深 | 主要、次要、輔助文字 |
| 演習 | `drill` `drill-fg` | 就是 `ink` | 演習標記條（上線時拿掉） |

- **兩個色相就夠**：一個主色（能做的事、已同意）、一個暖色（缺人）。其他全是中性色。第一版有藍、綠、橘、紫四個色相互相搶，這一版不要。
- **暖色只給缺人**，所以清單上第一眼跳出來的就是需要人的戶。
- **顏色從不單獨表意**：每個狀態都有字；形狀也帶意思——**虛線＝還沒確定**（尚未取得同意、還沒問到），實線框＝確定的「不」（不同意），填色＝確定的「是」或缺人。
- **對比**：每一組文字與底色都在 6.5:1 以上（WCAG 要求 4.5:1，我們在太陽底下看），邊框至少 3:1。`kb.py check` 會擋下不到的。
- **只有淺色主題**：主要在白天戶外用，陽光下淺底深字最好讀。

## 字

- **只用手機內建字型**：iPhone 的數字與英文是 SF、中文是蘋方；Android 是 Roboto 與思源黑體。**不載入網路字型**——災區網路不穩，中文字型檔很大。
- **用字重拉開層次**：標題與大數字 800、標籤與按鈕 700、內文 400。蘋方最粗到 600，中文在 iPhone 上會停在 600，數字照樣 800。
- **產品裡最小 15px**（`rq-t-meta`）。唯一例外是演習標記的 13px，它不是產品畫面。
- **字級**：`rq-t-display` 32 問題與標題／`rq-t-title` 28 回報頁地址／`rq-t-address` 20 清單上的地址／`rq-t-body` 17 說明／`rq-t-hint` 16 提示／`rq-t-label` 16 分類名／`rq-t-meta` 15 最後更新／`rq-t-button-lg` 20 答案按鈕／`rq-t-button` 18 膠囊按鈕／`rq-t-count` 42 分類數量／`rq-t-number` 34 人數。
- **數字用等寬**（數量、時間、人數），更新時排版不跳動。

## 間距、圓角、尺寸

- **4px 一格**（`space-1` 到 `space-8`）。清單頁左右 16，回報頁與問題頁左右 20。
- **觸控**：任何能按的東西至少 48px（`touch-min`，戴手套）；膠囊按鈕 56；答案按鈕 72，有副標 88；分類格 108。
- **圓角**：提示框 20、卡片與分類格 24、答案按鈕 28、其餘可以按的小東西膠囊形（`radius-pill`）。
- **強調框 2.5px**：展開的一戶、你剛剛在、要你先按的那一塊。

## 圖示

- Tabler Icons（MIT 授權）的十一個：返回、勾、叉、時鐘、走路、怎麼走、回報、加人、一群人、說明、鎖。線寬 2、24px 格，顏色跟著字。
- **一定跟字一起**。唯一的例外是返回鍵，它有 `aria-label="返回"`。不用 emoji。

## 畫面怎麼組

- **清單頁（下一戶去哪）**：演習標記 → 「下一戶去哪？」（`rq-t-display`）＋「你附近走路 15 分鐘內・近的排前面」→ CategoryGrid（四格大數字＋說明框）→ 這一類的 HouseholdRow，照走路距離排 → 底部鎖的圖示＋「不用登入，不問你是誰」。做完一戶回來時，最上面多一張 ResumeCard。
- **回報頁（一戶）**：演習標記 → TopBar「回報這一戶」→ 剛記下時的 Notice → 地址（`rq-t-title`）＋「只填你知道的那一項，不知道的留著」→ ReportCard 同意 → ReportCard 需求 → 回到清單。
- **問題頁（一題一頁）**：演習標記 → TopBar（地址）→ 問題（`rq-t-display`）＋一兩句說明（`rq-t-body`）→ 畫面下方一個答案一顆大按鈕，垂直排；最可能的答案用主色，「還沒確定」的答案用虛線。

## 明確不做

- 半透明、霧化（太陽下看不清楚）、陰影層次、動畫、網路字型、深色模式（這一版）。
- 只靠顏色的狀態、只有圖示的按鈕（返回鍵除外）。
- 排行、分數、打卡——工具不評比志工，也不問你是誰。

## 還沒定的

- 🚧 **網路不穩時**「還沒送出」的樣子。Notice 目前只有「已記下」一種；在那之前，「下一個打開的人會看到」只有真的送出後才能寫。
- 🚧 **陽光下實測**：淺色塊（`tonal`）和輔助文字（`ink-3`）在戶外夠不夠。
- 🚧 **清單預設停在哪一類**：交給兵推測（D-16）。

## 怎麼用

- 元件在 `components/bundle.js`，全域名稱 `window.ResQ`，需要頁面上已有 React 18。先載入 `components/bundle.css`，再載入 bundle.js。
- 可以按的元件都收 `href`（mockup 串頁用）或 `onClick`（真的 app 用）。
- `bundle.css` 最上面帶一份預設值（specificity 0）：沒載入 tokens.css 的地方照樣畫得出來；有載入時一律以 tokens.css 為準。
- 元件上的中文字是規格的一部分（D-16），不開放改字。要改字，先改規格。
