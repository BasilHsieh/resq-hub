# 面向工具的研究

> 給**要設計或做這個工具的人**：發起人、之後加入的工程師與設計師。研究看到的事，對工具「可能可以怎麼做」。
>
> **這不是規格，也不是決定，也不寫程式。** 規格只寫已經決定的（[spec/](../spec/)）；這裡的每一條都是候選，要經發起人決定，才會進規格、進程式。

## 現在有的

- [可能可以怎麼做](可能可以怎麼做.md)：照志工在哪個時刻用得到分節（出發前、到了車站、走在路上、到了那一戶、做完或離開、名單本身）；每一條寫可能可以怎麼做、為什麼、跟現在的做法、還不知道的。草稿。

## 怎麼做出來的

- 從 repo 根目錄 `knowledge/` 的研究筆記與研究清單的紀錄改寫，不另外上網找資料；出處與著作權的規則見[出處與著作權](../出處與著作權.md)。
- 每週的研究跑完，研究碰到哪一條，就改哪一條；新的想法加進來，標「候選」。
- 想法被決定了（進 DECISIONS 或規格），這裡那一條改成「已決定，見……」，不刪——為什麼這樣決定、當初還有哪些候選，比決定本身值錢。
