## 1. 這一版在展示什麼

- **前提**：志工在災區現場、剛做完一戶、站在門口，要決定下一戶去哪。
- **一個循環、三個畫面**：選下一戶 → 到了按一下（記下屋主同不同意）→ 做完按一下 → 回到選下一戶。第二輪起，挑新的一戶之前會先問剛才那戶。
- **同意這一層**（D-16）：家戶要先取得同意。「沒人在家」不會出現在任何畫面，別人只看得到「有人問過」。路段、側溝不用問。
- **清單一戶一戶列**，只照走路距離排；不用去的（人夠了、清完了、屋主說不用）不列，只算數量。
- **褪色**：用頁面底下的「演習控制」讓時間往前，可以看到「剛有人問過」變成「N 小時前有人問過」、人夠了三小時後回到清單、需求放十二小時標「情報已舊」。

## 2. 刻意不展示什麼

別人的回報（這一頁只有你一個人在按）、人會不會散開或擠在同一戶（那是兵推的事，見 [01-兵推](../01-兵推/README.md)）、地圖、導航、出發前那一頁、中繼站與遠端頁、「問了很多次都沒結果」轉給問里長的人、登入、多人連線。

## 3. 哪些是假的（全部）

| 項目 | 這一版的值 | 出處 |
|---|---|---|
| 時鐘 | 從 T+6 天 14:20 起；按「我到了」加走路分鐘，按「做完」加 2 小時 | 編的 |
| 地址與走路分鐘 | 15 個對象（13 戶、2 個路段） | 編的 |
| 門檻 | 人夠了 3 小時、清完了 24 小時、情報已舊 12 小時 | 沿用 spec §2 與 01 兵推，都是猜的 |

## 4. 傳給別人試之前

請對方用手機打開，照畫面上的情境走一輪，再問三題：

1. 你第一眼想點哪一戶？為什麼？
2. 按了「還沒取得」之後，你覺得下一個打開的人會看到什麼？
3. 哪裡看不懂、或按不到？

記對方的原話，不要先解釋。這是 D-15 核心假設（「看到沒人去過就會去」）與同意流程的第一批外部證據。

## 5. 檔案怎麼讀

`index.html` 用分隔線標了 KEEP／THROW：規則（`view`、`workView`）與畫面是 KEEP，必須跟 spec 一致；演習資料是 THROW。多人兵推的志工頁會用同一頁，只換資料來源（D-12）。按過的紀錄只存在那支手機的瀏覽器裡，不會傳給任何人。
