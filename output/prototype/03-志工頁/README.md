## 1. 這一版在展示什麼

- **前提**：志工在災區現場、剛做完一戶、站在門口，要決定下一戶去哪。
- **清單**：最上面四個分類（可以直接幫忙／要先問屋主／不同意／暫時不用去），直接寫數量；下面一戶一張卡，照走路距離排。
- **回報這一戶**：同意狀態和需求分成兩塊，各自更新，只填你知道的那一項（D-16）。
- **一題一頁**：屋主同意嗎？這一戶還需要人嗎？還要幾個人？答案放在畫面下方。
- **回到清單**：上方多一張「你剛剛在」，做完要離開時回到那一戶更新需求。

## 2. 刻意不展示什麼

別人的回報、人會不會散開或擠在同一戶（那是兵推的事，見 [01-兵推](../01-兵推/README.md)）、時間過去之後的褪色、地圖、導航、出發前那一頁、中繼站與遠端頁、「問了很多次都沒結果」轉給問里長的人、登入、多人連線、網路不穩時的樣子。

## 3. 傳給別人看之前

請對方照畫面上的情境點一輪，再問三題：

1. 你第一眼想點哪一戶？為什麼？
2. 按了「還沒問到」之後，你覺得下一個打開的人會看到什麼？
3. 哪裡看不懂、或按不到？

記對方的原話，不要先解釋。這是 D-15 核心假設（「看到沒人去過就會去」）與同意流程的第一批外部證據。畫布預設只有 Basil 打得開；要給別人看，從頁面的 Share 選單分享。

## 4. mockup 怎麼產生（給 Claude 與工程師；Basil 不用讀）

「流程」頁的 14 張，**正本在 repo**：`mockup/build.js` 用設計系統的元件把每一張組出來，輸出成畫布的格式。畫布只是發布出去給人看的版本，跟設計系統 artifact 一樣。要照著做一個真的能用的志工頁，看 repo 就夠：畫面在 `build.js`，元件在設計系統，規則在規格。

```bash
cd output/prototype/03-志工頁/mockup
npm install
node build.js --merge <從畫布讀回來的 project/canvas.json>
```

- 產出在 `mockup/out/project/`（不進 git）：14 張 `.dc.html`，加上合併好的 `canvas.json`——以線上那份為底，只換這裡管的部分（流程頁的畫面、標題、尺寸、便利貼、設計系統的安裝紀錄）；別人在畫布上拖過的位置、畫布自己存的欄位都留著。
- 發布（Claude 用 Artifact 工具）：一次送出 14 張、`canvas.json`，以及從設計系統 artifact 複製的三個檔：`project/ds/resq/tokens.json`、`project/ds/resq/components/bundle.css`、`project/ds/resq/components/bundle.js`。畫面的樣式全靠複製過去的 `bundle.css`，所以設計系統改了（例如換主色），畫布要重新複製一次。
- 「視覺方向」「主色」兩頁是做決定時的比較，已經決定（D-17），不再重產。
- 改畫面＝改 `build.js`。約定（Basil 2026-09-27，D-17）：人不在畫布上直接調整，都透過 AI 改 repo 再發布；流向是單向的 repo → 畫布。萬一畫布上被人改過，發布時工具會因為版本對不上而拒絕，那時先讀回來看改了什麼。

## 5. 封存：9/26 的舊版可點原型

2026-09-27 封存（Basil）。它是 mockup 之前的第一版：單一 HTML、可以在手機上點，流程是「選下一戶 → 到了按一下 → 做完按一下」，同意與需求綁在一起、時間寫「N 小時前」，都已被 mockup 取代。留在 repo 裡，接手的人或 AI 可能會照著舊流程做，所以移出目前的檔案。

- **程式**：在 git 歷史裡，commit `276128d` 的 `output/prototype/03-志工頁/index.html`（`git show 276128d:output/prototype/03-志工頁/index.html`）。
