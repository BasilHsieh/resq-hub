# 我們怎麼做研究

ResQ Hub 研究的是：全世界大型災害與戰爭中，政府和原本的救災團體忙不過來、大量志工湧入的時候，現場實際發生了什麼，包括清淤、物資、醫療站、收容。

研究由 AI（Claude）做，大部分時候自己跑：每週二晚上 11 點，額度還有剩就跑一批。發起人只在三個地方出手：丟來源、對檢驗題點頭、說「你 merge」。

## 兩種研究

| | 探索 | 檢驗 |
|---|---|---|
| 問的是 | 那裡發生了什麼？ | 這條論點站不站得住？ |
| 一次做 | 一個案例，照固定的欄位填 | 一條論點 |
| 動手前 | 欄位就是計畫 | 先寫三行：測什麼、什麼結果算推翻、找哪種人 |
| 誰點頭 | 不用：欄位固定，框錯的風險低 | 發起人看過三行才跑：問法幾乎決定答案 |
| 做出來的 | 一個案例，加上案例表的一列；沒想到的事寫成新的候選論點 | 判決：支持、挑戰、推翻，或沒影響 |

論點是 ResQ Hub 押的假設，例如「需要幫忙的戶沒人去，最大的原因是沒人知道」。論點的文字是發起人的話，研究不改它，只記它現在被支持還是被挑戰。

## 一份研究怎麼跑

### 1. 丟來源
- **誰**：發起人
- **做什麼**：看到相關的文章、報告，把連結貼在對話裡說「丟進研究清單」，或把檔案放進收件匣。不用說為什麼給。
- **留下什麼**：研究清單的收件匣
- **例子**：收件匣裡的東西，下一批研究最先處理。

### 2. 點頭
- **誰**：發起人
- **做什麼**：檢驗題先寫好三行：測什麼、什麼結果算推翻、找哪種人。發起人看過說可以，才會跑。探索不用點頭。
- **留下什麼**：研究清單上標「已點頭」
- **例子**：有一題要測「沒人去的地方，是因為不知道，還是因為不確定」，找的對象是捐款平台的捐款人：一樣是自願、選哪個都可以的人。

### 3. 挑工作
- **誰**：排程與 Claude
- **做什麼**：先看額度，夠才跑。照順序挑：收件匣、已點頭的檢驗題、案例佇列的下一個、消化已經有的資料。一批最多四份。
- **留下什麼**：一份計畫。探索的計畫就是案例的欄位，檢驗的計畫就是那三行。
- **例子**：案例的順序，是先挖最能回答「派工到底派出去多少、派得準不準」的地方。

### 4. 先查已經有的
- **誰**：Claude
- **做什麼**：上網找之前，先讀 repo 裡已經有的研究筆記與論文，寫下「已經有的」和「還缺的」。已經有的不重找。
- **留下什麼**：計畫裡的「已經有的」
- **例子**：2026-11-13 發起人提醒「不要忘了我們本來就找了一些論文」。給人看的頁面第一版，十四份台灣論文只用到兩份，之後才補上。

### 5. 找來源
- **誰**：三個 AI 助手
- **做什麼**：三個同時找，各找大約 50 次。探索照來源的種類分工：檢討報告與統計、學術研究、新聞與當事人。檢驗照立場分工：一個找支持的，一個專找反例，一個不給方向、自己找我們沒想到的。只能引用真的打開過的來源；要登入、要付費、被擋住的，不繞過，寫「打不開」。
- **留下什麼**：三份報告，每一條附書目、連結、讀到哪裡
- **例子**：2026-11-10 那一批，每個助手只找大約 30 次，找得太淺，之後改成大約 50 次。

### 6. 寫成研究筆記
- **誰**：Claude
- **做什麼**：把報告整理成研究筆記。每一條主張都標讀到哪裡（全文、只有摘要、別人的轉述、我們的推論），也標證據的種類（統計、研究、檢討、官方、報導、當事人的說法）。
- **留下什麼**：`knowledge/context/` 裡的一份研究筆記
- **例子**：發起人的現場觀察也會寫進去，但一律標「一個人的觀察，還沒查證」。不拿它蓋掉文獻，也不拿文獻蓋掉它。

### 7. 兩道審查
- **誰**：兩個 AI 助手
- **做什麼**：一個核引文：打開每個連結，比對原文跟筆記寫的一不一樣。一個核推論，找四種錯：比較的對象不像、結論越講越大、有別的解釋沒提、判決比證據強。找到的全部修掉或降級。
- **留下什麼**：修正過的研究筆記
- **例子**：Claude 曾經把「看過的六處」說成「全世界大型清淤幾乎都是派工」，其實六處裡就有一處刻意不派工。每一句引文都對，錯在推論一路長大；這種錯核引文抓不到，要核推論才抓得到。

### 8. 更新看板與案例表
- **誰**：Claude
- **做什麼**：論點看板上，被碰到的論點加一行證據，必要時改狀態。「被推翻」要兩個以上互相獨立的來源，而且至少一個是統計、研究或檢討。案例表加一列，研究清單記下這一題的結果。
- **留下什麼**：研究方向（論點看板）、案例比較表、研究清單
- **例子**：一位研究者某一天的現場觀察，在看板上只算「弱的支持」，論點的狀態不動。

### 9. 改寫給人看的頁面
- **誰**：Claude，再由一個 AI 助手審查
- **做什麼**：研究筆記是給 AI 看的：完整、有代號。給人看的手冊和知識庫，從研究筆記改寫成白話。每一頁都列出它根據哪些研究筆記，研究一改，就找得到要跟著改的頁。改完，另一個助手逐句對照研究筆記審查。
- **留下什麼**：手冊、知識庫、面向工具的研究
- **例子**：2026-11-13 的審查抓到，三位受訪的社工被寫成了同一個人，改成分開寫。

### 10. 給發起人一頁、開 PR
- **誰**：Claude
- **做什麼**：用一頁講完這一批：論點動了哪些、沒想到的事、要問發起人的現場題、等點頭的新題、這次動了哪幾頁、用掉多少額度。放進 GitHub 的 PR（請求合併的地方），不自己合併。
- **留下什麼**：一個 PR
- **例子**：每週二晚上跑完，週三早上會看到一個 PR。

### 11. 說「你 merge」
- **誰**：發起人
- **做什麼**：看過那一頁，說「你 merge」，而且 PR 上的自動檢查都通過了，Claude 才合併。合併之後，下一批研究就從新的版本開始。
- **留下什麼**：main 上的新版本
- **例子**：檢查沒通過，就不合併，先修。

## 怎麼讀我們的證據

每一頁的句子後面有註腳，註腳開頭的標示，說這句話有多確定。

**讀到哪裡**

- 〔全文〕讀過整份原文
- 〔摘要〕只讀到摘要
- 〔二手〕從別人的轉述讀到的
- 〔推論〕我們自己的讀法，不是來源說的

**證據的種類**（強的在前）

- 〔統計〕有分母的數字
- 〔研究〕論文、個案研究、問卷
- 〔檢討〕政府或 NGO 事後的檢討報告
- 〔官方〕政府的公告與說明
- 〔報導〕新聞
- 〔當事人〕當事人的說法，包括發起人的觀察（研究筆記裡寫成〔自述〕）

最強的證據只是新聞、當事人的說法或推論時，正文裡會直接說出來，例如「據新聞報導」「一位志工的觀察」。寫法的規則見[出處與著作權](../出處與著作權.md)。
